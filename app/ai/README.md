# app/ai/ — model provider boundary (OpenRouter)

## What this folder is
Everything that knows about the AI provider. Services depend on the `OpenRouterClient` interface defined here, never on `fetch`, so tests pass a fake and no automated test makes a billable call. Nothing in this folder is imported by browser code.

| File | Exports | Notes |
|---|---|---|
| `config.server.ts` | `loadAiConfig(env?)`, `resolveModel(config, requested?)`, `AiConfigError`, type `AiConfig` | Reads `OPENROUTER_API_KEY`, `OPENROUTER_MODELS` (comma-separated allowlist, first = default), optional `OPENROUTER_BASE_URL`, `OPENROUTER_DATA_COLLECTION` (`deny` default, or `allow`), `OPENROUTER_TIMEOUT_MS` (60000), `OPENROUTER_MAX_RETRIES` (2), `AI_MAX_OUTPUT_TOKENS` (1500), `AI_MAX_IMAGES` (4, max 4), `AI_DAILY_LIMIT_PER_SHOP` (50), `AI_MAX_CONCURRENT_PER_SHOP` (1), `AI_RESEARCH` (`on` default / `off`), `AI_RESEARCH_MAX_SEARCHES` (3, 1-5), `AI_RESEARCH_MAX_RESULTS` (5, 1-10). Parsed lazily, so the app boots without a key and only generation reports "not configured". Numbers are range-checked. `resolveModel` rejects any model outside the allowlist before a provider call |
| `openrouter-client.server.ts` | interface `OpenRouterClient`, types `GenerationRequest`, `GenerationResult`, `WebSearchOptions`, `Citation`, `ChatMessage`, `ChatContentPart`, `AiProviderError`, `AiErrorKind` | The contract services depend on. Error kinds mirror `ShopifyApiError`: TRANSPORT, TIMEOUT, RATE_LIMITED (retryable) and AUTH, REFUSED, INVALID_OUTPUT, UNSUPPORTED (not). `GenerationRequest.webSearch` (`{ maxUses, maxResults }`) turns one request into a research call; `GenerationResult.citations` (unique http(s) URLs from `url_citation` annotations, with titles) and `searchCount` (`usage.server_tool_use.web_search_requests`) report what the search really did |
| | `createOpenRouterClient(config, deps?)`, `classifyStatus(status, detail)`, `extractCitations(annotations)` | `POST {baseUrl}/chat/completions` with `response_format: json_schema` (strict), `provider: { require_parameters: true, data_collection }`, `usage: { include: true }`, `temperature` 0.4. With `webSearch`: `tools: [{ type: "openrouter:web_search", parameters: { max_uses, max_results, max_total_results } }]` and `max_tool_calls`, so OpenRouter runs the searches server-side (model decides when) and one request returns the final cited answer; both caps bound the spend. Per-attempt `AbortSignal.timeout`. Retries only retryable kinds, at most `maxRetries` times, backoff 1s/2s or the `Retry-After` header; a wait above 15s fails instead. 401/402/403 → AUTH, 408 → TIMEOUT, 429 → RATE_LIMITED, 5xx → TRANSPORT, other 4xx → UNSUPPORTED. An `error` inside a 200 body is classified the same way. Refusal / `content_filter` → REFUSED; empty content or `finish_reason: length` → INVALID_OUTPUT, with the finish reason, the output token count and (for `length`) the limit in the message, so "stopped while still searching" (`tool_calls`) and "out of output tokens" can be told apart. Missing `usage` is not an error. `fetch`, `sleep`, `now` are injectable for tests |

## Rules
- The API key never leaves the server: not in loader data, not in logs, not in error messages (`AiConfigError` names the variable, never its value).
- `GenerationResult.content` is untrusted until validated and sanitized by the service.
- Only allowlisted models are called. They must accept image input AND structured outputs AND tool calling (the research call sends the web search tool, and `require_parameters` refuses an endpoint that ignores it); a router model such as `openrouter/free` is not acceptable because the model that answers would be unknown. If the model cannot take tools, research fails as UNSUPPORTED and the description is still generated.
- A citation is evidence the search tool returned that page; it is not evidence the page says what the model claims. The research validator in `services/description-output.ts` uses citations only to reject sources the search never returned.
- Logs carry model, attempt, latency, generation id, usage numbers, whether web search was on, the search count and the number of citations. Never the key, the Authorization header, the prompt, image URLs, cited URLs or the answer. Usage fields are logged as `usagePrompt` / `usageCompletion` because the logger redacts any key containing "token".
- Invalid or refused answers are not retried: the same prompt would fail the same way and every call spends quota.
